# RPS Rivals — project guide for Claude

Two brothers build this game together: Dainis (owner) and his brother (GitHub: kalninskaspars11-spec). Both use Claude.
Answer them in Latvian unless they write in another language.

## What the game is
RPS Rivals (formerly "Space Duel") is a 3D rock-paper-scissors browser game. Name chosen Nov 2026; planned domain rpsrivals.com (not bought/connected yet). Internal ids keep the old prefix on purpose: `sd_*` tables/functions, `sd-models` bucket, Realtime channels `spaceduel-*` (renaming them would break saved data and online play between versions).
- Live: https://tenmost.github.io/gametest/ (GitHub Pages, deploys from `main` about a minute after a push)
- Three.js 0.170 from jsDelivr, no build step, no npm. Everything runs as plain HTML + JS.
- Goal: earn money with it later, so every asset and library must be licensed for commercial use.

## Files
- `index.html` — the whole game (CSS + several `<script>` blocks). Large and dense; edit with small, targeted changes.
- `admin.html` — admin panel: upload/remove characters, view stats. Admins only (checked server-side).
- `astronaut-test.html` — older experiment page, not linked from the game.
- `assets/*.glb` — built-in character models (Meshy, rigged/animated). Other characters are uploaded through the admin panel to Supabase storage (`sd-models` bucket).
- `supabase/player_profiles.sql` — player accounts migration (applied as `sd_player_profiles`): profiles, server-verified matches vs computer, arena unlocks.
- `tools/optimize_glb.py` — shrink a new Meshy/Mixamo GLB (mesh, textures, keep chosen animations).
- `tools/reduce_keyframes.py` — drop redundant animation keyframes; run with `--verify` to see the max motion error.

## Design decisions (keep these unless the brothers change them)
- Moves are shown as cards (rock/paper/scissors), not finger gestures. Keep the 3D character models.
- No hand/arm pumping before the reveal; each character does a show-off move (dance, karate, etc.).
- Characters "talk" with text speech bubbles only — no voices.
- Announcer ("ROUND 1 – FIGHT!", "MATCH POINT", fight won/lost, victory/defeat) = big on-screen text + heavy Web Audio sounds (booms, gong, brass chords) + a deep male announcer voice via browser text-to-speech (`announceVoice`, pitch 0.1). The brothers chose this; characters themselves still have no voice. No audio files yet — a recorded, commercially licensed announcer voice may replace the TTS later.
- During a match the HUD shows a big square avatar in each top corner (`.hudAv`, size `--avs`) with the player name + a shorter health bar beside it (`.label`, `.hearts`), not the character's name. Hover/tap the avatar → `.hudTip` with stats (`fillHudTip`: wins, losses, matches, win %, streak, best; vs computer = matches won against you; an online opponent shows only their public mini card: cup + the 3 numbers they chose on their player card, never crystal counts — presence fields `card` [[icon,label,value]×3] from `window.sdCardPublic()` and `cup`; the same mini card `#oppCard` appears in the online room as soon as the friend joins (`showOppCard`)). The old `.score` line is hidden. `setHud(p,c)` takes `{av, k (avatar key, 'cpu' for computer), name, st}`. Vs computer the opponent is "🤖 COMPUTER"; online the opponent's name and avatar come from presence (`name`, `av`). Status texts use `oppName()`.
- CHRISTMAS THEME (automatic 20 Nov – 6 Jan, or `?xmas=1` / `?xmas=0` to force): `window.SD_XMAS` + `html.xmas` class set by the first inline script. Logo: white "RPS" with red shadow, green "RIVALS", Santa hat on the first R (`#brandLogo .l1::before`, inline SVG), sub line "MERRY CHRISTMAS". 3D background: Earth at night (dark texture + `emissiveMap` city lights, snowy land, thinner clouds) with ~700 tiny snowy houses with lit windows (InstancedMesh on `earthM`, so they turn with the planet); Santa's sleigh + 5 reindeer (Rudolph's nose glows) flies across low through the open middle (below the mode buttons) like the UFOs (`makeSanta`, `updateXmas`), leaves a glitter trail and drops presents (`dropGift`; UFOs help too — presents fall out of their green beam) that fall onto the planet; meteor strikes are off. UFOs still fly.
- Tall stylized toy-figure characters with normal proportions (not chibi).
- Before every round the START ROUND screen runs a 10 s auto-start countdown (`startReadyCountdown`, `#readyCount`: number grows, yellow at 6, red + tick at 3; at 0 it presses START itself, also online) so an AFK player can't block the other one.
- Match = best of three fights, each fight has three health segments; random card if the pick timer runs out. ARENA RULES (`MAP_RULES` in index.html, shown on the arena cards and in the ? rules dialog): pick timer temple 10 s, city 6, ice 8, lava 7, jungle 8, factory 10, nebula 9 (`pickTime()`); Forgotten Graveyard (`factory`) = SUDDEN DEATH, one fight decides the match (`fw:1`, `FW()` / `matchFW`). Crystal Nebula (`nebula`) = BEST OF 5, first to 3 fights (`fw:3`; card chip "★ BEST OF 5"). Signed in vs computer the server decides fights-to-win (`sd_match_start2(map)` → `{id, fw}` + `sd_match_play` uses `fights_to_win`, `supabase/map_rules.sql`); with an older server the client falls back to `sd_match_start()` and best of 3.
- Crystals: blue (💎, spendable) and pink (`pink_crystals`, shown with a hue-rotated 💎 `.pinkGem`; earned by inviting friends + social daily missions, spent on the mythic Cosmic Phoenix avatar; later also real money / rare events). Signed-in players: blue crystals, wins/losses and unlocked arenas live in `sd_player_profiles` (server). Guests: no crystals at all (the old local test balance `sd_demo_progress_v1` is no longer used). Reward codes are redeemed only inside the profile window (signed in) via `sd_redeem_code(code)`: the server compares SHA-256(upper(code)) with `sd_reward_codes` (only hashes stored, `active` flag) and allows each account one redemption per code (`sd_code_redemptions`).
- EXIT MATCH button (`#matchExit`) shows only on the START ROUND screen (`#stage.waiting-fight-ready`). It warns first; leaving = lost match, no rewards. Signed in vs computer it calls `sd_match_forfeit` (loss, 0 crystals, losses +1, streak reset) — see `supabase/match_forfeit.sql`.
- Player name: free when the profile is created; changing it later costs 150 blue crystals (`NAME_PRICE` in index.html + `sd_set_username` in `supabase/username_price.sql`, keep in sync). Register/setup forms warn about it; rename needs a second CONFIRM click.
- Crystal counters: instant hover tooltip (`data-tip`, "saved to your profile" / "log in to earn") and a click opens `#gemInfo`: how to earn blue crystals, what they unlock (arenas, name change, characters coming soon); pink = coming soon (real money / rare events).
- Profile stat tiles (`.acStat`) have hover/tap tooltips (`data-tip`, texts in `TIPS` in the crystal-info script); the crystals tile opens `#gemInfo`.
- Avatars: 16 free + 15 premium bought with blue crystals + 1 mythic bought with 100 PINK crystals (phoenix, `AV_CUR`, hidden until `pink_crystals` exists) (cheap 25: moon, satellite, octopus, ghost · rare 100: unicorn, shark, ninja, vampire · epic 300, glowing: flame, bolt, galaxy, crystal_ball · legendary 750, glowing + moving: vortex, crown, dragon_king). `AV` / `AV_PRICE` in index.html must match `sd_avatar_price()` in `supabase/premium_avatars.sql` (`unlocked_avatars` column, `sd_unlock_avatar`, `sd_set_avatar` checks ownership). Premium avatars are original drawn pictures in `assets/avatars/<key>.svg` (made for this game, free to use commercially; same cartoon style: dark outline, gradients, own background); legendary ones (vortex, crown, dragon_king) animate inside the SVG (SMIL). `avatarFill()` (`window.sdAvatarFill`) shows the picture for premium keys and the emoji for free ones; glow = CSS on `[data-tier]` / `[data-av]`. Premium avatars stay hidden if the `unlocked_avatars` column is missing. Clicking a locked one opens `#avBuyDialog` (`avBuy()`: preview, tier, price, balance, Unlock or "How to earn").
- No blinking text cursor / text selection anywhere except text fields (`caret-color:transparent` + `user-select:none` on html/body/dialogs) — it showed up when clicking the game with the browser's caret browsing on.
- Start screen layout (≥700 px wide, CSS block "START SCREEN LAYOUT"): left column = player card + HERO COLLECTION (2 columns), centre = title, mode buttons and the 3D hero (`layoutSelect` puts it at x .15), right column = READY + ARENA COLLECTION (`#mapPick` buttons turned into `.mpCard` cards: picture from `Scene3D.previewArena`, name, rule chip, `.mpLock` price). Centre: the RPS RIVALS logo as the title (`#brandLogo` h2 + small "ROCK · PAPER · SCISSORS DUELS" line; no "CHOOSE YOUR PLAYER" heading — the bottom hint already says pick your fighter), Logo font Lilita One (Google Fonts, OFL); start-screen panels are frosted see-through glass (block "LOGO + GLASS PANELS") so the moving space scene shows through. VS COMPUTER / ONLINE as a two-part pill switch with a small sub line (`.onCount` shows how many players are online), the hint (`#selHint`) as a pill at the bottom centre. The long help footer is replaced by the `#rulesBtn` ? dialog; `#fsBtn` ⛶ toggles browser full screen (whole page, stage grows to fit). Under 700 px the old stacked layout stays.
- Start screen player card (`#playerCard` in `#accountBar`, top-left corner): big avatar + player name + blue/pink crystal counters + DAILY + the ☰ account menu (`#accountToggle` moved inside, menu opens under it), and a row of 3 stats under the avatar — the player clicks a slot to choose what it shows (wins, losses, matches, win %, streak, best, crystals, pink, arenas, cups; `STATS`, saved per device in localStorage `sd_card_stats`; default wins / win % / streak; '–' for guests). The best match cup shows next to the name. Compact on narrow screens (stats + DAILY hidden under 700px). Clicking the avatar or the name opens the profile at the avatar picker (guests: log in). Avatars can only be changed on the start screen / profile, never during a match.
- Achievements: match cups for 100 / 500 / 1K / 5K / 10K / 50K / 100K / 500K / 1M finished matches vs computer (wins + losses from the server profile): Bronze, Silver, Gold, Platinum, Emerald, Sapphire, Ruby, Diamond, Cosmic (`CUPS`, `window.sdCups(m)`, cup pictures generated as SVG). ACHIEVEMENTS section `#acCups` in the profile under the stats (locked cups grey, progress bar on the next one).
- Daily login streak (`supabase/login_streak.sql`): `sd_daily_login()` once per page load for signed-in players (UTC days counted by the server; every 7th day in a row +15 blue, every 30th +60 blue +2 pink; toast `.sdToast`). Badges 7 / 30 / 100 / 365 days in ACHIEVEMENTS (by best streak); 📅 LOGIN is a card stat option. Hidden if the function is missing.
- Phones: portrait = whole page blurred + "turn your phone sideways" (`#rotateMsg`, CSS `orientation:portrait` + `pointer:coarse`); landscape = one-time "play full screen?" prompt (`#fsAsk`, only where `document.fullscreenEnabled`, also tries `screen.orientation.lock('landscape')`). The stage is sized to fit the screen height too (`main` width uses `100dvh*16/9`), the footer is hidden on touch screens.
- Arena cards use a floating game-style tooltip (`#tipFloat`, `data-tip`), not the browser's title tooltip; on phones the rule chip on the card is enough.
- Account menu (☰): guests see LOG IN + REGISTER + PLAY AS GUEST; signed-in players see PROFILE + LOG OUT.
- Guests get no rewards: no crystals, only the free arena (Orbital Temple), no name entry (they appear as "Guest123"). Guests also keep no stats at all: every guest match stands on its own (the in-memory `stats` only counts for signed-in players; the game-over text and HUD tips say the guest game isn't saved). Crystals, unlocks, player name, avatar and friends need an account.

## Arenas (performance rules)
- Arenas are built in code (`temple` + `alternate.{city,ice,lava,jungle,factory,nebula}`; Crystal Nebula = floating pink crystal platform, its own shiny materials are skipped by the arena material pass, floating shards animate in `updateArenaFX`), then `bakeStatic()` merges all static scenery into a few meshes per arena (one per material type, colours become vertex colours). This cut draw calls ~5–10× (e.g. graveyard ~1270 → ~210 per 2 frames).
- What gets baked: opaque Standard/Basic meshes that are direct children of the arena group, or inside a group with `userData.staticDecor=true`. Anything that moves or changes material at runtime (animals, flames, hands, mist, particles) must be in its own sub-Group or have `userData.dynamic=true` on the mesh or its material — otherwise it will be frozen into the baked mesh.
- New scenery must be added before the bake call (just above `fightArena.visible=false;scene.add(fightArena)`).
- Arena rules: Neon City = 6-second pick timer. Rejected by the brothers (don't add): frozen/unavailable cards, hiding the opponent's previous cards, character abilities. Lava wave (bigger damage) is still being discussed — it would need the server (`sd_match_play`) to know the arena.
- Arenas react to match events (`Scene3D.arenaHit(who,big)` from `runRound` on every lost health segment, bigger when a fight ends; `Scene3D.setFinal(on)` = red pulsing light + dimmed arena in the final round). Code: `updateArenaFX` — lava flares + embers, ice flash + penguins hop + bear rears, city neon flickers, jungle bird flies off, graveyard hand grabs + owls look. Only lights, particles and non-baked sub-groups are touched.
- Ambient particles (`PARTS`, `updateParticles`): snow in Frozen Temple, embers in Volcanic Cavern — one `Points` draw call each.

## Supabase
- Project URL and the publishable key are in `index.html` / `admin.html` (the publishable key is public by design).
- NEVER put a `service_role` key, database password or any secret in the repo, a chat or a screenshot.
- Game tables use the `sd_` prefix: `sd_characters`, `sd_rounds`, `sd_matches`, `sd_admins`; admin RPCs `sd_is_admin`, `sd_is_owner`, `sd_admin_*`, `sd_stats`.
- The game runs on the shared Supabase project `mrrqfrmgblbgrvkbrwvt` ("tenmost's Project"), which it shares with Dainis's site tenmost.com. The separate "Space Duel" project (`urfdxhnkyytcypexrogo`) was deleted in Nov 2026.
- In that project, only touch the game's own objects: `sd_*` tables and functions and the `sd-models` storage bucket. Never change or delete any other table, function, policy, bucket or setting — they belong to tenmost.com.
- Admins are listed in `sd_admins` (email only). The owner is decided by tenmost.com's `user_roles` table via `has_role(..., 'admin')` inside `sd_is_owner()` — read it, never change it. Only the owner can add/remove admins and set their passwords.
- Player accounts: Supabase Auth (email + password, shared with tenmost.com's auth) + `sd_player_profiles` (unique player name, avatar, crystals, wins, losses, unlocked arenas/characters). Profile window (`#accountDialog`): log in / register tabs, then avatar picker (emoji avatars; keys must match the check list in the DB and `AV` in index.html), name change (`sd_set_avatar`, `sd_set_username`), stats. Password: change in the profile (`auth.updateUser`); "Forgot password?" sends `resetPasswordForEmail` with `redirectTo` = the game URL, and the `PASSWORD_RECOVERY` auth event opens the "new password" view. The game URL must be in Supabase Auth → Redirect URLs (a tenmost.com setting — only Dainis changes it); otherwise the reset link goes to tenmost.com's Site URL. Clients can only SELECT their own row; every change goes through security-definer RPCs.
- Matches vs computer for signed-in players are server-verified: `sd_match_start()` creates a row in `sd_cpu_matches`, `sd_match_play(match, move)` picks the computer's card on the server, tracks health/fights and, when the match ends, adds crystals (win 8 perfect / 5, loss 1) and wins/losses. Min. 1 s between rounds. The client just plays the animation with the card the server returned.
- Win streaks: `current_streak` / `best_streak` in `sd_player_profiles`, updated by the trigger `sd_cpu_matches_streak` when a match vs computer ends (online matches don't count yet). Profile shows wins, losses, matches, win %, streak, best streak.
- Friends (`supabase/friends_and_streaks.sql`): table `sd_friends` (requester, addressee, pending/accepted), no direct client access — RPCs `sd_friend_request(username)` (auto-accepts if they already asked you), `sd_friend_respond(id, accept)`, `sd_friend_remove(id)`, `sd_friends_list()` (friends' stats only once accepted). UI is the FRIENDS section in `#accountDialog`; incoming requests show 🔔 next to the player name.
- Arena unlocks: `sd_unlock_map(map)` checks price + balance on the server (prices: city 20, jungle 35, ice 50, lava 75, factory 100 blue; nebula 50 PINK — `supabase/pink_arena.sql`; keep them in sync with `prices` / `PINK_MAPS` in index.html). Online the guest always plays the host's arena (no unlock needed); the host's HOST MAP buttons use the same locks as the start screen.
- Social features (`supabase/social.sql`): invite link `?ref=<first 8 chars of user id>` stored in localStorage and claimed once by a NEW account via `sd_claim_referral` (+1 pink +10 blue to the inviter, +5 blue to the newcomer; `sd_my_invites`, INVITE FRIENDS section `#acInvite` in the profile); `window.sdShareGame()` shares/copies the invite link; the share3 mission counts only REAL visits: when someone else opens a `?ref=` link the visitor's browser calls `sd_share_visit(code)` (anon OK, once per browser per day) and the server counts distinct visitor IPs (md5) per sharer per day, max 3, ignoring the sharer's own account and own network (`sd_daily_share` now only records the sharer's IP and returns the count — `supabase/share_visits.sql`); online matches with friends count only when BOTH signed-in players call `sd_online_report(room, opp uid, won)` and the reports pair up (presence carries `uid`).
- Daily missions (`supabase/daily_missions.sql`, extended by `social.sql`): 3 rotating per day from a pool of 6 + 2 social every day (share3, online3: +1 pink each), reset 00:00 UTC; the DAILY button pulses while missions are open and flashes when one can be claimed; progress computed on the server from `sd_cpu_matches` (forfeits don't count); `sd_daily_missions()`, `sd_daily_claim(mission)` → crystals. UI: 📋 DAILY button in `#accountBar` + `#dailyDialog`; hidden if the server functions are missing.
- Online matches do not give crystals yet (no trusted verifier for two-browser matches).
- Rewards (crystals, unlocks) must never be granted by a browser call that trusts the client. Spending must be checked server-side (price + balance).

## Online multiplayer
- Supabase Realtime channel `spaceduel-<ROOM>`; presence for the lobby, broadcast for game events.
- Moves use commit-reveal: `pick` sends only a SHA-256 hash (round:move:salt); `reveal` sends move + salt after both players have committed. Do not send the plain move in `pick` — that lets the opponent read it before choosing.
- Both players must run the same version; after changing the protocol, both reload.

## Working together
- Always `git pull` before starting and push small commits with clear messages, so the two brothers' changes don't collide.
- Agree who is working on what; avoid both editing the same part of `index.html` at the same time.
