## What the game is
RPS Rivals (formerly "Space Duel") is a 3D rock-paper-scissors browser game. Name chosen Nov 2026. Domain: joyjoy.gg (bought Nov 2026 at GoDaddy, meant as the main domain for all of Dainis's future games; DNS = 4 GitHub Pages A records on @ + CNAME www → tenmost.github.io; `CNAME` file in the repo — don't delete it). Internal ids keep the old prefix on purpose: `sd_*` tables/functions, `sd-models` bucket, Realtime channels `spaceduel-*` (renaming them would break saved data and online play between versions).
- Live: https://joyjoy.gg/ (GitHub Pages custom domain; the old https://tenmost.github.io/gametest/ redirects there; deploys from `main` about a minute after a push). localStorage and the login session are per address, so players had to log in again once after the move. Supabase Auth → Redirect URLs must include https://joyjoy.gg/ for password reset links.
- SITE HEADER (v1.10.2): `#siteHdr` inside `<main>` above `#stage` = JOYJOY.GG logo (Lilita One, JOY gold / JOY pink / .GG teal) + slogan "Enjoy Good Games" (Dainis's choice; colours since v1.10.3: "En" yellow, "joy" pink, "Good Games" teal like .GG), top-centre over the game frame. Height `--hdrH` (62px) is subtracted from `main`'s width formula so the game still fits; hidden (and `--hdrH:0`) on portrait phones, screens under 600px high and in full screen — the game's ⛶ (`html:fullscreen`) and the browser's F11 (`html.fsOn`, set by a small script right after the header style: window as big as the screen; plus `display-mode:fullscreen`). The loading screen `#sdBoot` shows the same JOYJOY.GG logo + coloured motto at the top (`.bJJ`, replaced the old "A JOYJOY.GG GAME" footer). Browser tab (v1.11.2): `<title>` and og:title = "JOYJOY.GG — Enjoy Good Games", favicon = inline SVG (dark rounded square, gold J + pink J + teal dot). Clicking the header logo `.jjLogo` (v1.12.2, script in the SOCIAL LINKS block) = back to the lobby by clicking `#topNav .tnBrand`; only while `#stage.selecting` (class `#siteHdr.home`), does nothing during a match.
- Three.js 0.170 from jsDelivr, no build step, no npm. Everything runs as plain HTML + JS.
- Goal: earn money with it later, so every asset and library must be licensed for commercial use.

Since v1.5.0 every clip's Hips x/z is pinned to the bind position in the GLB (Meshy clips like All_Night_Dance / Knock_Down start off-centre and the game only locks x/z to the FIRST frame, so heroes jumped sideways). Do the same for new heroes with `tools/glb_clips.py` (--rename, --center, --trim, --cut, --cap, --face, --report). Since v1.8.3 every hero GLB is also run with `--face`: Meshy clips start with the body turned 20–70° (frog idle −50°), so heroes looked away from the opponent and spun during cross-fades; `--face` turns the Hips so the HEAD faces forward at the start of every clip (and slides the correction along a clip that ends turned >20°). Run it on new heroes too (after --center). The live roster is the `sd_characters` table (enabled rows); the old heroes (tv, cosmic, mushmaare, msspike, spacehead) are rows with `enabled=false` (their uploaded files are still in `sd-models`), and the old repo models (Space Girl, Azure, TV Head, Cosmic) were deleted from `assets/`. The built-in `CHARS` list in index.html is only the fallback. `animChar` picks clips by NAME patterns per phase (fight = box|punch|guard|jab|fight|kick|combat|dodge|axe.chop|attack, win = victory|cheer|celebrat|backflip|triumph, hit = hit|hurt|stagger|pain|defeat|stomp|electrocution, dead = dead|death|defeat|fall|behit|knock|tantrum), so show-off clips whose Meshy name doesn't match are RENAMED in the GLB (e.g. `Combat_Flex_Muscles`, `Combat_Seed_Throw`). New hero pipeline: `optimize_glb.py --no-simplify --tex 1024 --keep …` → `reduce_keyframes.py` → rename clips → `assets/` + an `sd_characters` row.
- Very round/fat characters animate badly with Meshy's library moves (arms go into the belly, belly stretches with the legs) — prefer normal body shapes.
- `supabase/player_profiles.sql` — player accounts migration (applied as `sd_player_profiles`): profiles, server-verified matches vs computer, arena unlocks.
- `tools/optimize_glb.py` — shrink a new Meshy/Mixamo GLB (mesh, textures, keep chosen animations).
- `tools/reduce_keyframes.py` — drop redundant animation keyframes; run with `--verify` to see the max motion error.

## Design decisions (keep these unless the brothers change them)
- Moves are shown as cards (rock/paper/scissors), not finger gestures. Keep the 3D character models.
- No hand/arm pumping before the reveal; each character does a show-off move (dance, karate, etc.).
- Characters "talk" with text speech bubbles only — no voices.
- Announcer ("ROUND 1 – FIGHT!", "MATCH POINT", fight won/lost, victory/defeat) = big on-screen text + heavy Web Audio sounds (booms, gong, brass chords) + a deep male announcer voice via browser text-to-speech (`announceVoice`, pitch 0.1). The brothers chose this; characters themselves still have no voice. No audio files yet — a recorded, commercially licensed announcer voice may replace the TTS later.
- During a match the HUD shows a big square avatar in each top corner (`.hudAv`, size `--avs`) with the player name + a shorter health bar beside it (`.label`, `.hearts`), not the character's name. Hover/tap the avatar → `.hudTip` with stats (`fillHudTip`: wins, losses, matches, win %, streak, best; vs computer = matches won against you; an online opponent shows only their public mini card: cup + the 3 numbers they chose on their player card, never crystal counts — presence fields `card` [[icon,label,value]×3] from `window.sdCardPublic()` and `cup`; the same mini card `#oppCard` appears in the online room as soon as the friend joins (`showOppCard`)). The old `.score` line is hidden. `setHud(p,c)` takes `{av, k (avatar key, 'cpu' for computer), name, st}`. Vs computer the opponent is "🤖 COMPUTER"; online the opponent's name and avatar come from presence (`name`, `av`). Status texts use `oppName()`.
- CHRISTMAS THEME (automatic 20 Nov – 6 Jan, or `?xmas=1` / `?xmas=0` to force): `window.SD_XMAS` + `html.xmas` class set by the first inline script. Logo: white "RPS" with red shadow, green "RIVALS", Santa hat on the first R (`#brandLogo .l1::before`, inline SVG), sub line "MERRY CHRISTMAS". 3D background: Earth at night (dark texture + `emissiveMap` city lights, snowy land, thinner clouds) with ~700 tiny snowy houses with lit windows (InstancedMesh on `earthM`, so they turn with the planet); Santa's sleigh + 5 reindeer (Rudolph's nose glows) flies across low through the open middle (below the mode buttons) like the UFOs (`makeSanta`, `updateXmas`), leaves a glitter trail and drops presents (`dropGift`; UFOs help too — presents fall out of their green beam) that fall onto the planet; meteor strikes are off. UFOs still fly.
- Tall stylized toy-figure characters with normal proportions (not chibi).
- Before every round the START ROUND screen runs a 10 s auto-start countdown (`startReadyCountdown`, `#readyCount`: number grows, yellow at 6, red + tick at 3; at 0 it presses START itself, also online) so an AFK player can't block the other one.
- Match = best of three fights, each fight has three health segments; random card if the pick timer runs out. ARENA RULES (`MAP_RULES` in index.html, shown on the arena cards and in the ? rules dialog): pick timer temple 10 s, city 6, ice 8, lava 7, jungle 8, factory 10, nebula 9 (`pickTime()`); Forgotten Graveyard (`factory`) = SUDDEN DEATH, one fight decides the match (`fw:1`, `FW()` / `matchFW`). Crystal Nebula (`nebula`) = BEST OF 5, first to 3 fights (`fw:3`; card chip "★ BEST OF 5"). Signed in vs computer the server decides fights-to-win (`sd_match_start2(map)` → `{id, fw}` + `sd_match_play` uses `fights_to_win`, `supabase/map_rules.sql`); with an older server the client falls back to `sd_match_start()` and best of 3.
- Crystals: blue (💎, spendable) and pink (`pink_crystals`, shown with a hue-rotated 💎 `.pinkGem`; earned by inviting friends + social daily missions, spent on the mythic Cosmic Phoenix avatar; later also real money / rare events). Signed-in players: blue crystals, wins/losses and unlocked arenas live in `sd_player_profiles` (server). Guests: no crystals at all (the old local test balance `sd_demo_progress_v1` is no longer used). Reward codes are redeemed only inside the profile window (signed in) via `sd_redeem_code(code)`: the server compares SHA-256(upper(code)) with `sd_reward_codes` (only hashes stored, `active` flag) and allows each account one redemption per code (`sd_code_redemptions`).
- EXIT MATCH button (`#matchExit`) shows only on the START ROUND screen (`#stage.waiting-fight-ready`). It warns first; leaving = lost match, no rewards. Signed in vs computer it calls `sd_match_forfeit` (loss, 0 crystals, losses +1, streak reset) — see `supabase/match_forfeit.sql`.
- Player name: free when the profile is created; changing it later costs 150 blue crystals (`NAME_PRICE` in index.html + `sd_set_username` in `supabase/username_price.sql`, keep in sync). Register/setup forms warn about it; rename needs a second CONFIRM click.

- Avatars: 16 free + 15 premium bought with blue crystals + 1 mythic bought with 100 PINK crystals (phoenix, `AV_CUR`, hidden until `pink_crystals` exists) (cheap 25: moon, satellite, octopus, ghost · rare 100: unicorn, shark, ninja, vampire · epic 300, glowing: flame, bolt, galaxy, crystal_ball · legendary 750, glowing + moving: vortex, crown, dragon_king). `AV` / `AV_PRICE` in index.html must match `sd_avatar_price()` in `supabase/premium_avatars.sql` (`unlocked_avatars` column, `sd_unlock_avatar`, `sd_set_avatar` checks ownership). - No blinking text cursor / text selection anywhere except text fields (`caret-color:transparent` + `user-select:none` on html/body/dialogs) — it showed up when clicking the game with the browser's caret browsing on.

Older description, still true for the parts not moved: ARENA COLLECTION (`#mapPick` buttons turned into `.mpCard` cards: picture from `Scene3D.previewArena`, name, rule chip, `.mpLock` price). Centre: the RPS RIVALS logo as the title (`#brandLogo` h2 + small "ROCK · PAPER · SCISSORS DUELS" line; no "CHOOSE YOUR PLAYER" heading — the bottom hint already says pick your fighter), Logo font Lilita One (Google Fonts, OFL); start-screen panels are frosted see-through glass (block "LOGO + GLASS PANELS") so the moving space scene shows through. ## Arenas (performance rules)
- Arenas are built in code (`temple` + `alternate.{city,ice,lava,jungle,factory,nebula,atlantis,desert,pirate,dragon,celestial}`; the five newest (block "FIVE NEW ARENAS", helpers `nw*`, animation in `animateNewArenas`, refs in `NEWA`) each have their own gradient sky dome (`nwSky`, hides the planet/asteroids via `updateBackground`): Sunken Atlantis (ruins, coral, kelp, fish, jellyfish, caustics, bubbles), Desert Mirage (pyramids, obelisks, oasis palms, vultures, tumbleweed, drifting sand), Pirate Cove (ship deck at night, sails, waving skull flag, cannons, gold, lanterns, sea), Dragon Peak (floating sky islands, waterfalls, cherry trees, red gate, a big dragon flying a loop + petals), Celestial Palace (marble + gold colonnade, throne, turning zodiac halo, orbs, light pillars). Prices (Nov 2026, `UNLOCK_ALL_MAPS=false` again): temple, city, ice FREE (price 0 = owned by everyone, guests too); jungle 35, lava 75, factory 100, atlantis 150, desert 200, nebula 250, pirate 300, dragon 400 blue; celestial 120 PINK — the only pink arena (`supabase/arenas_more.sql`, `prices`/`PINK_MAPS`). Rules: atlantis 9 s, desert 7, pirate 8, dragon 8, celestial ⚡ BLITZ 5 s; Crystal Nebula = floating pink crystal platform, its own shiny materials are skipped by the arena material pass, floating shards animate in `updateArenaFX`), then `bakeStatic()` merges all static scenery into a few meshes per arena (one per material type, colours become vertex colours). This cut draw calls ~5–10× (e.g. graveyard ~1270 → ~210 per 2 frames).
- What gets baked: opaque Standard/Basic meshes that are direct children of the arena group, or inside a group with `userData.staticDecor=true`. Anything that moves or changes material at runtime (animals, flames, hands, mist, particles) must be in its own sub-Group or have `userData.dynamic=true` on the mesh or its material — otherwise it will be frozen into the baked mesh.
- New scenery must be added before the bake call (just above `fightArena.visible=false;scene.add(fightArena)`).
- Arena rules: Neon City = 6-second pick timer. Rejected by the brothers (don't add): frozen/unavailable cards, hiding the opponent's previous cards, character abilities. Lava wave (bigger damage) is still being discussed — it would need the server (`sd_match_play`) to know the arena.
- Arenas react to match events (`Scene3D.arenaHit(who,big)` from `runRound` on every lost health segment, bigger when a fight ends; `Scene3D.setFinal(on)` = red pulsing light + dimmed arena in the final round). Code: `updateArenaFX` — lava flares + embers, ice flash + penguins hop + bear rears, city neon flickers, jungle bird flies off, graveyard hand grabs + owls look. Only lights, particles and non-baked sub-groups are touched.
- Ambient particles (`PARTS`, `updateParticles`): snow in Frozen Temple, embers in Volcanic Cavern — one `Points` draw call each.

## Supabase
- Project URL and the publishable key are in `index.html` / `admin.html` (the publishable key is public by design).
- NEVER put a `service_role` key, database password or any secret in the repo, a chat or a screenshot.
- Game tables use the `sd_` prefix: `sd_characters`, `sd_rounds`, `sd_matches`, `sd_admins`; admin RPCs `sd_is_admin`, `sd_is_owner`, `sd_admin_*`, `sd_stats`.
- The game runs on the shared Supabase project `mrrqfrmgblbgrvkbrwvt` ("tenmost's Project"), which it shares with Dainis's site tenmost.com. The separate "Space Duel" project (`urfdxhnkyytcypexrogo`) was deleted in Nov 2026.
- In that project, only touch the game's own objects: `sd_*` tables and functions and the `sd-models` storage bucket. Never change or delete any other table, function, policy, bucket or setting — they belong to tenmost.com.
- Admins are listed in `sd_admins` (email only). The owner is decided by tenmost.com's `user_roles` table via `has_role(..., 'admin')` inside `sd_is_owner()` — read it, never change it. Only the owner can add/remove admins and set their passwords.
- ONE Supabase client only: both `client` (account script) and `sbClient()` share `window.__sbP` / `window.__sb` (persistSession + autoRefreshToken). Two clients raced to refresh the same saved session (seen in auth logs as two token_refreshed in the same second), which can drop the login on refresh — never call createClient anywhere else.
- Player accounts: Supabase Auth (email + password, shared with tenmost.com's auth) + `sd_player_profiles` (unique player name, avatar, crystals, wins, losses, unlocked arenas/characters). Profile window (`#accountDialog`): log in / register tabs, then avatar picker (emoji avatars; keys must match the check list in the DB and `AV` in index.html), name change (`sd_set_avatar`, `sd_set_username`), stats. Password: change in the profile (`auth.updateUser`); "Forgot password?" sends `resetPasswordForEmail` with `redirectTo` = the game URL, and the `PASSWORD_RECOVERY` auth event opens the "new password" view. ## UPDATES + VERSION NUMBER (both brothers' Claudes MUST do this on every update)
- The game has a version number like a normal game: `SD_VERSION` in index.html (block "UPDATES + SHINE", last block) and `version.json` (`current` + `releases`, newest first). Players see it in the 📰 WHAT'S NEW window (📰 button left of 🎓 on the start screen, also in the ? window). The window opens by itself once after each new version (not for brand-new players, not during a match; localStorage `sd_seen_ver`).
- EVERY push that players can notice (feature, fix, look change) = a new version. Before pushing:
  1. `git pull` first. Look at the top of version.json — if your brother already used the next number, take the one after it.
  2. Pick the number: fix / small polish → PATCH +1 (1.0.0 → 1.0.1); new feature or new content → MINOR +1 and PATCH 0 (1.0.1 → 1.1.0); huge relaunch → MAJOR (only when Dainis says).
  3. Add a release at the TOP of `releases` and set `current` to it: `{"v","date" (YYYY-MM-DD),"title" (short),"new":[...],"fixed":[...]}`. Write lines for players (simple English, kids play this): what they can do now / what works again. No code names, no file names.
  4. Set `const SD_VERSION='x.y.z'` in index.html to the SAME number.
  5. Run `python3 tools/check_version.py` — it must print ✓. Mention the version in the commit message (e.g. "v1.1.0: …").
  - Several commits for one feature in one session can share one version: update that release's lines instead of making a new number each commit. Internal-only changes (CLAUDE.md, tools, tests) need no new version.
- Live update banner: open games fetch version.json (no cache) every 3 min and when the tab comes back; if `current` is newer than the loaded SD_VERSION a gold banner "🆕 Update vX is ready — RELOAD" shows on the start screen (never covers a match). So bumping the number is what tells players to reload.
- SHINE = "not done yet" on the start screen: 🎓 shines until the tutorial is done (`sd_tut_done`), 📰 shines + red dot until the newest version was read, the 📋 DAILY button on the player card shines while missions/rewards are open (`#dailyBtn.has` / `.todo`). New "unfinished" things: add them to `paint()` in that block with class `sdShine`.
